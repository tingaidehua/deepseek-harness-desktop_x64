# 会话工作树

`dsh-tauri-worktree` 是 Desktop 内置插件，不是 DSH 开发模式功能。它在 Git 项目中为单个会话创建隔离的 Git Worktree，使 Agent 的代码修改不会直接污染用户当前分支。

## 界面与可用性

输入框的「工作模式」选择器提供「本地」和「工作树」。选择「工作树」后，下一条消息会在隔离目录中开始新会话。工作树会话的输入框上方会显示状态条、创建日志、「检出本地」和「放弃」操作，会话列表同时显示分支标识。

正式构建默认把该插件的 Host 与 Client 制品按精确 DSH 核心版本放入安装包。`pnpm verify:bundled-plugins` 会阻止缺少工作树 Host 路由或 Client 界面的发布。只有显式设置 `DSH_DESKTOP_BUNDLE_EXTENSIONS=0` 的干净 DSH 基线测试不携带 Desktop 插件。

## 数据与控制流

1. Client 插件把用户选择保存为下一条消息的工作模式。
2. Host 插件根据源会话的工作目录解析 Git 项目，在 DSH 数据目录的 `worktrees/<hash>/<repo>` 下创建隔离工作树，并记录会话绑定。
3. 新会话的 `cwd` 指向该工作树，因此文件、终端、源代码管理和 Agent 工具看到同一份隔离状态。
4. 「检出本地」在用户明确确认后创建本地分支、携带工作树变更并把会话交还本地工作区。
5. 「放弃」归档会话，删除临时工作树及由插件拥有的临时分支。

Desktop 自动化矩阵同时检查模式选择器、会话 ID 和 `/api/dsh-worktree/status` Host 路由，因此不需要靠人工点击才能发现 Client 已加载但 Host 未加载的半失效状态。

## 适用场景

- 并行功能开发：每个会话使用独立工作树，多个 Agent 不会互相覆盖文件。
- 方案对比：对同一需求建立多个实现会话，审核后只检出选中方案。
- 紧急修复：无需收藏当前未完成工作，先在隔离工作树中完成修复。
- 安全试验：重构、依赖升级、代码生成和批量修改可随时放弃，不影响主工作区。
- 业务任务隔离：把客户需求、运营活动或数据处理任务映射为可审核、可丢弃、可转交的独立变更单元。

## 限制

- 只有 Git 项目可以选择工作树；普通目录保持本地模式。
- Git Worktree 共享仓库对象数据，但每个工作树有独立检出文件和索引；依赖目录与构建缓存是否共享取决于项目自身配置。
- 工作树变更与本地当前变更重叠时，检出可能产生 Git 冲突；失败时保留工作树，不应丢失变更。
