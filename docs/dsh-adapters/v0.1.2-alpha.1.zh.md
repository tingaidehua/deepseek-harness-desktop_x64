# DSH `0.1.2-alpha.1` Desktop 适配记录

## 摘要

本记录覆盖 Desktop 从保留核心 `0.1.1-rc.2` 迁移到 `0.1.2-alpha.1` 的过程。目标版本引入了 Web 认证启动、拆分后的客户端包图、更严格的扩展注册和 fail-closed 持久化数据读取。这些变化暴露了 Desktop 对 URL、Host 所有权、可变核心目录、无版本插件、profile 补丁和人工验证的错误假设。

## 核心更新

### Web 认证就绪

Web bundle 会等待 Loader 结算和 Connection 服务，通过 `connection.authenticatedUrl()` 创建进程 token URL，将该 URL 输出为就绪信号，并把认证 URL 交给浏览器。认证交换建立 HttpOnly `SameSite=Strict` Cookie；未执行交换的干净源 URL 不是已认证应用会话。

这是合理的核心安全增强。监管进程必须消费输出的 URL，但不能记录或持久化 token；必须为 Cookie 保持同站导航，并区分供展示的干净服务 URL和携带凭据的 WebView URL。

### 客户端包拆分

单体 `@deepseek-ai/dsh-client-runtime` 包已移除。Store 基础设施迁移到 `@deepseek-ai/dsh-client-store`，Session、Workspace、Conversation、Chat、Approval 等职责迁移到各自领域包。API Proxy 传输也被 Connection 自有和领域 Remote 接口取代。

因此，针对 `@deepseek-ai/dsh-client-runtime/client` 编译的插件无法在目标包图中激活。包名替换只能桥接狭窄的 Store 导入；依赖已删除 Runtime 行为的插件必须从源码迁移到新的领域所有者。

### Loader 与 slot 所有权

Client modules 和 UI slots 依赖明确的所有者表，并通过 `ctx.slots.inject()` 延迟贡献。贡献者在声明所有者到达前直接注册 `settings.section` 时可能被拒绝激活，而不是依赖偶然加载顺序静默成功。

这项更新使扩展所有权具有确定性。插件制品必须声明负责物化客户端模块的包，并通过受支持的 injection 路径向延迟声明的 slot 贡献。

### Host 信任与浏览器权限

目标版本将 WebRuntime authority 与 Connection 浏览器权限分开。路由所有者读取 `ctx.webRuntime.trustedHosts`；设置持久化和 Host API 访问依赖 Connection 对浏览器是否持有本地 Host 的判断。嵌入式别名不会自动等价于字面值 `127.0.0.1` 源。

因此 Desktop 必须分别声明两个事实：DSH 接受 `dsh.tauri.localhost` 作为可信 runtime authority，嵌入式浏览器持有这个只监听回环地址的 Host。只设置 Connection 路由值不会更新路由所有者；只设置 runtime 信任不会授予设置持久化权限。

### 持久化会话词汇

目标版本按照必需词汇读取持久化会话事件，并拒绝未知事件类型。预发布版本线不承诺跨版本会话格式，因此 `0.1.1-rc.2` 可能拒绝 `0.1.2-alpha.1` 写入的会话。

Desktop 必须展示拒绝信息，但不能崩溃或改写事件。静默转换会虚构核心语义，使后续恢复更不可靠。

## 实际冲突

| 现象 | 直接原因 | 根因 |
| --- | --- | --- |
| 启动后出现 `ERR_CONNECTION_REFUSED` 或空白壳 | Desktop 在认证就绪 URL 可用前发起导航 | 生命周期把端口监听当作完整 Web 就绪，并用同一个 URL 承担展示和认证导航 |
| 插件 Loader 报告 `dsh-client-runtime/client` 缺少模块表 | RC 时代插件 bundle 导入了目标版本已删除的包入口 | 插件没有按客户端 ABI 世代固定并构建；Desktop 仅根据包名假设 npm 包兼容 |
| Better Sidebar chunks 和路由返回 `forbidden` | `ctx.webRuntime.trustedHosts` 不包含 `dsh.tauri.localhost` | Desktop 修改了 Connection 层配置，但独立路由所有者使用 WebRuntime authority |
| 模型和插件设置提示设置不可用 | 别名不满足字面回环/Host 所有权判断 | Desktop 把 URL 可达性、信任和浏览器 Host 权限视为同一概念 |
| `dsh-tauri-session` 可能拒绝整个插件图 | 制品在所有者表存在前直接注册 `settings.section` | 插件激活依赖 RC 的偶然加载顺序，而不是目标 slot injection 契约 |
| 切换核心或核心路径缺失会停止服务或使壳崩溃 | 核心选择会移动目录，错误越过生命周期处理 | 核心存储、选择、插件投影和进程状态耦合在一次可变操作中 |
| 插件设置期间弹出 GitHub 登录或出现网络行为 | 启动过程安装了浮动 Git 来源或 registry 包 | 将运行时安装当作部署；制品缺少固定、离线、按世代区分的来源证明 |
| RC 无法接受 alpha 会话并显示校验错误 | 会话包含 RC 不认识的事件 | 这是有意的预发布格式边界，不是 Desktop 插件缺陷 |

核心更新确实使认证、包导出、slots 和会话词汇发生不兼容。大量调试成本并非只由这些更新造成；更主要的原因是 Desktop 把核心假设分散在 workflow、React、profile、可变目录和无版本插件安装中。

## 架构更改

### 不可变核心槽位

每个打包核心位于 `dependencies/cores/<tag>`。`dependencies/active-core` 选择活动制品。切换会先校验目标，只停止自有进程，更新指针和设置，重新绑定插件；失败时回滚指针、设置、插件投影和服务状态。

### 版本自有适配器世代

`DshAdapter` 将已安装包版本解析为 `legacy-web` 或 `authenticated-web-v1`。适配器负责启动参数、可选 `--no-open`、就绪 URL 解释、认证 WebView 导航和私有 WebRuntime overlay。未知未来世代会在启动前失败，不会继承最新已知行为。

### 干净产品 profile

`product-zhiliao-zhihuiguan` 从官方 `dsh-base` 和 `dsh-web-app` 初始化。Desktop 兼容行位于 `dsh-adapters/<family>.cordis.yml`，不进入官方核心、官方 Web profile 或用户 `cordis.patch.yml`。

### 管理插件投影

Desktop 持久化选中的逻辑插件 ID。构建准备从固定包版本或 Git revision 生成 `legacy-web` 和 `authenticated-web-v1` 制品。切换核心时，将所选世代安装到内容寻址 profile 路径，并在启动前运行静态兼容门禁。

### 明确的嵌入式 Host 所有权

认证适配器将 `dsh.tauri.localhost` 加入权威 `web-runtime.trustedHosts` 列表。WebView 初始化脚本只为该应用控制的 authority 声明 Host 所有权；它不会为任意远程源授予回环权限。

### 将诊断作为产品接口

壳通过 IPC 记录 frame 就绪和功能面检查，通过 Tauri 和独立 CLI 暴露只读诊断快照，并让 WebView2 遍历脚本共享 `surface-contracts.json`。错误文档、Loader 失败、插件 ID 缺失、延迟资源失败、设置不可用和侧栏失败文本都成为命令行断言。

## 插件结果

在 alpha 适配器中，选中后通过验收的启动图包含 `dsh-tauri`、`dsh-tauri-ui`、`dsh-tauri-worktree`、`dsh-tauri-panel`、`dsh-tauri-panel-extension`、`dsh-tauri-session`、`dsh-tauri-rightclick`、`dshmarket`、`dsh-better-sidebar` 和 `dsh-notification`。

`dsh-win-terminal-inspector` 保持为仅 legacy 使用的预设，因为 alpha 核心已提供相关 Windows 行为。认证世代不包含它属于明确能力决策，不是安装失败。

Desktop 矩阵证明组合、资源加载和声明功能面。插件仓库仍负责 Worktree 创建、归档变更、终端进程行为和通知投递等破坏性领域操作。

## 验证

最终实现通过 292 个 Rust 库测试、TypeScript 类型检查、JavaScript 语法检查、diff 卫生检查、alpha 真实 frame 功能面矩阵和保留 RC 矩阵。RC 测试报告预期的 alpha 会话不兼容拒绝，同时壳保持可操作。

矩阵断言真实启动图、认证 frame 就绪、全部声明的延迟资源、模型与插件设置页、Better Sidebar 内置标签、Tauri panel 功能面，以及不存在已知 Loader、授权和设置失败特征。

## 剩余债务

semver 到世代的映射仍编译在 Desktop 中。未来的能力清单应让打包 DSH 制品明确声明就绪、认证、客户端 ABI、Loader 和会话世代。

构建过程目前会对旧插件制品执行少量转换，包括 Store 导入和一处 slot 注册。固定兼容的上游插件版本后必须删除这些转换；禁止将其扩展为通用 JavaScript 改写层。

功能面矩阵验证非破坏性集成路径。它不能取代插件自有的状态变更端到端测试，也不能建立跨预发布版本会话兼容承诺。

## 下一版适配指导

从干净官方目标开始，将声明或观察到的协议与 `authenticated-web-v1` 比较。如果只有包版本变化，重新构建并验证同一世代。如果就绪、认证、客户端 ABI、Loader 或会话世代变化，应先增加新世代和新版本记录，再修改 workflow 或 UI 代码。

如果适配仍反复修改 adapter、插件投影或诊断清单之外的代码，就应视为兼容边界仍不完整。目标不是保存 Desktop 的旧假设，而是让 Desktop 以第一方壳应有的纪律消费 DSH 当前公开契约。
